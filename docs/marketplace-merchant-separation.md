# فصل تطبيق العملاء عن مواقع التجار

## القرار

سيكون Marketplace تطبيق عملاء مستقلًا لا يظهر داخله اسم أو شعار التاجر، بينما الموقع المنشور لكل تاجر يعمل كتجربة مستقلة بهوية التاجر وسلته وcheckout الخاص به. لوحة التاجر وWebsite Builder تظل تطبيقات داخلية منفصلة.

## الحدود الحالية

| الجزء                                       | المسارات/التطبيق                                                             | الهوية                               | السلة والطلبات                                                          | الحالة                        |
| ------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------ | ----------------------------------------------------------------------- | ----------------------------- |
| تطبيق العملاء Marketplace                   | `/`, `/dalil`, `/shops`, `/product`, `/offers`, `/search`, `/profile` وغيرها | هوية Marketplace فقط                 | `CartProvider` وcheckout العام، مصدر الطلب `marketplace`                | متوقف مؤقتًا في الإنتاج       |
| الثيم الموحد للتاجر داخل التطبيق            | `/shop/:slug`                                                                | إطار التطبيق + محتوى التاجر          | `CartProvider` (سلة الماركت لكل متجر) و`/shop/:slug/checkout`           | يعمل — للتاجر غير المنشور فقط |
| قالب التاجر المدمج (احتياطي للرابط المباشر) | `/shop/:slug?view=site`                                                      | هوية التاجر                          | `SiteCartProvider` (سلة الموقع) وcheckout الموقع `/site/:slug/checkout` | يعمل                          |
| الموقع المنشور من Builder                   | `/site/:slug` + الدومين الفرعي/المخصص                                        | شجرة Builder المحفوظة وبيانات التاجر | `SiteCartProvider` لكل تاجر وcheckout الموقع                            | يعمل                          |
| لوحة التاجر وBuilder                        | `apps/dashboard-web`                                                         | هوية Business/Dashboard              | طلبات التاجر وعمليات POS                                                | يعمل                          |

## بوابة الإيقاف

في الإنتاج، Marketplace العام يعرض `/coming-soon` افتراضيًا. إعادة تشغيله تحتاج متغير النشر:

```env
NEXT_PUBLIC_MARKETPLACE_LIVE=true
```

مواقع `/site/:slug` و`/shop/:slug` وcheckout الخاص بها مستثناة من البوابة، لذلك لا تتأثر بقرار إيقاف Marketplace.

## قواعد الهوية

- عنوان المتصفح وfavicon لموقع التاجر يستخدمان اسم وشعار التاجر.
- `AppChrome` لا يضيف Navbar أو Footer الخاصين بـ Marketplace داخل صفحات التاجر — بفحص المسار `/shop/*` و`/site/*` وأيضًا الهوست (موقع على دومين فرعي/مخصص = مفيش كروم للماركت).
- لا يتم استخدام شعار Marketplace داخل header الخاص بالموقع المنشور؛ الـ Builder أو renderer الخاص بالتاجر هو مصدر الحقيقة.
- السلة الخاصة بموقع التاجر مخزنة في `sessionStorage` بمفتاح `merchant-site-cart:site:{slug}` (الـ slug بييجي صريح من `app/site/[slug]/layout.tsx` — مش من `usePathname` — عشان تشتغل على الدومين الفرعي/المخصص)، ولا تختلط بسلة Marketplace (`mnmknk_cart`).

## سياسة التنقل (الخريطة والكروت والبحث)

التاجر المنشور (`websitePublished` = `builder_published_config` + `builder_published_at` موجودين — نفس قاعدة pins الخريطة) بيفتح موقعه المنفصل من كل مداخل الماركت **بنفس التاب** على `/site/:slug` — تنقل عادي جوه نافذة التطبيق، وزر الرجوع بيرجّع للماركت. التنقل العادي ممنوع يفتح تاب خارجي أو دومين فرعي:

| المدخل                                   | التاجر المنشور                  | التاجر غير المنشور          |
| ---------------------------------------- | ------------------------------- | --------------------------- |
| كروت المتاجر (الدليل/الرئيسية/المقترحات) | `/site/:slug` — بنفس التاب      | `/shop/:slug` بالثيم الموحد |
| نتائج البحث                              | `/site/:slug` — بنفس التاب      | `/shop/:slug` بالثيم الموحد |
| روابط المتجر في صفحة المنتج              | `/site/:slug` — بنفس التاب      | `/shop/:slug` بالثيم الموحد |
| pins الخريطة                             | `/site/:slug` — بنفس التاب      | `/shop/:slug` بالثيم الموحد |
| زر «الموقع الرسمي» في صفحة المتجر        | الرابط العام الحقيقي — تاب جديد | الزر مش ظاهر                |

الرابط العام الحقيقي (دومين فرعي/مخصص — لينك منشئ الصفحات اللي التاجر بيروجع ليه بنفسه) بيتفتح فقط من زر «الموقع الرسمي» الصريح أو من لينك التاجر نفسه بره الماركت — التنقل العادي جوه التطبيق مبيسيبش نافذة التطبيق أبدًا.

العلم بيجي من باك اند على كل استجابات المتاجر العامة (`/shops`، `/shops/:slug`، `/search/shops`) وخريطة القيم `websitePublished`.

## مراحل الفصل القادمة

1. إبقاء Marketplace متوقفًا مع مراقبة طلبات مواقع التجار وظهورها في لوحة التاجر.
2. نقل كود Marketplace العام إلى تطبيق/حزمة عميل مستقلة، مع إبقاء renderer والـ checkout الخاصين بمواقع التجار في حزمة storefront مستقلة.
3. فصل متغيرات البيئة والنشر: نطاق Marketplace، نطاق Dashboard، ونطاقات المواقع أو domains الخاصة بالتجار.
4. إضافة عقد API واضحة:
   - `marketplace` للطلبات متعددة التجار.
   - `website` لطلب موقع تاجر واحد.
   - `dashboard` للطلبات الداخلية والتحديثات.
5. بعد تجميع التجار، إعادة تفعيل Marketplace تدريجيًا دون تعديل كود مواقع التجار.

## ممنوعات الفصل

- لا نوقف `/site/:slug` أو `/shop/:slug` عند إيقاف Marketplace.
- لا نستخدم cart واحدًا مشتركًا بين Marketplace وموقع التاجر.
- لا نضع شعار المنصة كـ fallback ظاهر في header موقع التاجر إذا كان شعار التاجر متاحًا.
- لا نغير عقد الطلبات أو مصدر الطلبات دون اختبار ظهورها في لوحة التاجر.
